# ACP tutorials

Every setup step and configuration screen has a short GIF, regenerated by
`npm run tutorials:record` (S12). The recorder binds only to the testids listed in
`docs/ACP-UI-CONTRACT.md`, because the owner will replace the UI and re-run the recorder.
The registry table `tutorials` holds the key, audience, ordered steps, media path and `ui_hash`;
`scripts/check-tutorials.mjs` fails the build when an Appendix A key has no registry row or no GIF,
and warns on a stale `ui_hash`.

## Keys recorded so far

| Key | Audience | Screen | Steps (plain language) |
|---|---|---|---|
| `oa.escalation` | org_admin | OA-13 escalation rules | 1 Open the Org Admin control plane. 2 Open the Escalation tab. 3 Press "New escalation rule". 4 Choose the event it watches. 5 Add the conditions that must hold. 6 Set the recommendation template (the recommendation is decided by the rule, never by AI). 7 Save. |
| `oa.escalation-cards` | org_admin | WK-08 escalation cards | 1 Open the Work Queue. 2 Find "Escalations for you". 3 Read the recommendation and its reason. 4 A CIA opens a proposal and starts a plan; the plan still goes through the deployment gate. |
| `oa.boardpack-use` | org_admin | WK-01 Dashboard Board Pack panel | 1 Open the Dashboard. 2 Find the Board Pack panel. 3 Read the detected last pack: date, hash and whether it chains to a previous pack. |
| `oa.boardpack-generate` | org_admin | WK-02 Board Pack generator | 1 In the Board Pack panel, type a scope. 2 Choose the boundary: since the last pack, a custom range, or since the last board meeting. 3 Press Generate. |
| `oa.boardpack-view` | org_admin | WK-03 Board Pack web view | 1 Open a pack from the history. 2 Read the snapshot hash. 3 Every figure shows the record behind it; use the sources index to trace a number. |
| `oa.boardpack-download` | org_admin | WK-04 downloads and verify chip | 1 Open a pack. 2 Press PDF or PPTX. 3 The file carries a hyperlink on every figure. 4 Scan the QR to verify the pack without signing in. |
| `oa.boardpack-config` | org_admin | OA-09 Board Pack configuration | 1 Open the Board Pack panel. 2 Open the Sections tab. 3 Turn a section on or off. 4 Move a section up or down. A section is never deleted. |
| `oa.timetravel` | org_admin | WK-09 Time-Travel | 1 Open an engagement in the Audit File window. 2 Open the Time-Travel view. 3 Drag the handle or use the previous/next buttons to snap to a recorded event. 4 Read the state as it was. 5 Press "Compare with now" to see what was added, changed or removed. Everything is read-only. |
| `oa.patterns` | org_admin | WK-10 Patterns | 1 Open the Issues & CAP Register. 2 Switch to the Patterns view. 3 Read the groups of similar findings. 4 Click a node, a heat-map cell or a group member to open the original sealed finding. 5 Open Settings to change the thresholds. |
| `sa.hosting-fit` | super_admin | SA-10 hosting fit check | 1 Open the platform portal. 2 Open the Hosting fit tab. 3 Search for the client's stack by name or alias. 4 Fill the short questionnaire. 5 Read the verdict (Green, Amber or Red), the cost tier and the reasons. 6 Read the checklist of what the client must provide. |
| `sa.hosting-rules` | super_admin | SA-11 hosting rules editor | 1 Open the Hosting fit tab. 2 Open the Rules sub-tab. 3 Edit a rule's field, operator, value and severity. 4 Turn a rule on or off. No JSON is typed anywhere. |
| `sa.migration` | super_admin | SA-12 migration jobs | 1 Open the platform portal. 2 Open the Migration jobs tab. 3 Pick a tenant. 4 Read each job's status, step progress and retention window. 5 Read the Deployment Kit for the client's own deployment. |
| `oa.hosting` | org_admin | OA-15 hosting and database | 1 Open Organisation settings. 2 Open the Hosting tab. 3 Enter the target database kind, host, port, database and username. 4 Enter the password; it is stored encrypted and never shown again. 5 Save. |
| `oa.migration` | org_admin | OA-15 migration | 1 On the Hosting tab, press "Start migration" beside a connection. 2 Copy the runner command. 3 Run it on a machine that can reach both databases. 4 Watch the steps in the portal. |
| `oa.deployment-kit` | org_admin | OA-15 deployment kit | 1 After migration, read the Deployment Kit. 2 Add VITE_SUPABASE_URL and VITE_SUPABASE_PUBLISHABLE_KEY. 3 Deploy the front end to free static hosting. |
| `oa.retire-old` | org_admin | OA-15 retire the old connection | 1 Wait out the retention window (read-only, default 14 days). 2 Press and hold "Retire old connection" to confirm. 3 The old connection is retired after an export hash is recorded. |

Keys for the other Appendix A screens are registered by their own slices (S1 to S13). A key with no
row here yet is not yet recorded; `docs/ACP-UI-CONTRACT.md` names the key for each screen.
