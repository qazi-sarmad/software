# Design brief — the designer's catalogue

This catalogue belongs to the **designer**. It carries no product code. It carries the catalogue a
redesign is drawn from, and the boundary of what may be drawn yet.

It lives on the trunk, `feature/systeligon-builder-continuous`, so it is always generated against the
current build — the design branch `design/language-v1` carried the first draft, and this
copy supersedes it (regenerated against the trunk's 122 screens, not the draft's 105).

Read `docs/DESIGN-SPEC.md` first. It is **auto-generated** and always current; this brief explains how
to read it and what is out of scope.

---

## What is here

| File | What it is | Hand-edit? |
|---|---|---|
| `docs/DESIGN-SPEC.md` | Every screen, every flow, every design token and the typography system — generated from the code | **No** — run `npm run gen:design` |
| `docs/UI-INVENTORY.md` | The per-screen catalogue the spec is built from: purpose, route, rights, data functions, RPCs, testids, states, explain ids, IIA standards, drilldown targets | **No** — generated by `scripts/gen-ui-inventory.mjs` |
| `docs/ACP-UI-CONTRACT.md` | The authored interface: one section per screen, the stable testids | **Yes** — this is the source of truth |
| `docs/DESIGN-BRIEF.md` | This file | Yes |
| `src/guards/designSpec.test.ts` | Fails if the spec drifts from its sources | — |

## The one rule: the spec auto-updates, so never edit it

`docs/DESIGN-SPEC.md` is generated by `scripts/gen-design-spec.mjs` from `docs/UI-INVENTORY.md`,
`docs/ACP-UI-CONTRACT.md`, `src/lib/tutorialKeys.json`, `public/tutorials/` and `src/styles/tokens.css`.
Regenerate it with:

```
npm run gen:design
```

The `designSpec` guard regenerates into a temp file and requires the committed file to match
byte-for-byte. **If you edit the spec by hand, the guard fails.** Edit a source and regenerate
instead. When a screen gains a testid or a flow is recorded, the spec moves on its own after a
regenerate — that is the point of the file.

## What the spec gives you

- **Screens** — every screen the product carries, with the facts a redesign must preserve. The
  **testids are the stable contract**: a Playwright spec and the tutorial recorder bind only to them,
  so a redesign keeps every testid. Each screen also names its **data functions, data modules, RPCs
  and tables** — the calls it makes. A redesign moves the chrome, never the call.
- **Flows** — every recorded tutorial is an ordered walk over one screen's testids. It is the closest
  thing to a user journey the product has, and the best description of how a screen is used.
- **Design tokens** — every variable, per preset (Ledger, Porcelain, Bone) and theme (light, dark).
  A redesign replaces the *values*; the *names* are the interface the components read, so a name stays
  and only its value changes.
- **Typography** — the self-hosted font system. A new typeface ships **in the bundle** via
  `@fontsource`; it is never a remote link. That is a tenancy requirement (L2), not a preference.

## What is out of scope — the design language is not settled

The owner has **not** settled the design language, so these rows are **DEFERRED by instruction**.
Drawing them now means redrawing them. They are listed at the top of `docs/DESIGN-SPEC.md`:

**E8** `PencilGuide` · **U5** motion signalling state change only · **U7** density toggle · **U9**
three themes (`prism`, `bloom`, `slate`) · **U10** four audience profiles · **U11** time-of-day
phases · **U12** motion system · **U13** animated headers · **A-U1** pencil-pointer surface.

When the owner settles one, it moves out of the deferred table in the same commit that builds it.

## Laws a design must respect

These are not style guidance — they are enforced in code and a design that breaks them cannot ship.

- **No blocking modals.** Non-modal chrome is `role="complementary"` (the tutorial player is a
  drawer, not a modal).
- **Every interactive element carries `data-testid="<screenId>-<element>"`.** The testid is the
  contract; keep it.
- **Every screen is honest in five states** — loading / empty / error / ready / denied. Never a wall
  of zeros, never a silent blank, never a denied screen that looks like an empty one. (This is row
  A-U2, functional, and it is build work on the builder branch, not a design decision.)
- **No external font or asset host.** Everything ships in the bundle.
- **Data never leaves the tenant.** A screen reads through `src/data/*.ts`; a component never imports
  the database client.

## How a change flows back

A redesign that needs a new testid, a new state or a changed route is a change to the **contract**,
not to the spec. Make it in `docs/ACP-UI-CONTRACT.md`, regenerate the derived views
(`npx tsx scripts/gen-ui-inventory.mjs` then `npm run gen:design`), and the guards stay green. The
builder branch consumes the same contract, so the two stay in step by construction.
