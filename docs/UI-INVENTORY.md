# UI inventory — the single source of truth for the parallel UI redesign

Generated by `scripts/gen-ui-inventory.mjs` from `docs/ACP-UI-CONTRACT.md`, `src/data/*.ts`,
`src/lib/tutorialKeys.json` and the testids that exist in `src/`. It is a *derived* view: the
contract stays the authored interface; this file is the flat catalogue a designer can read
without opening the code. Screens are grouped by area; each entry gives screenId, purpose, route,
rights, data functions, RPCs/tables, every data-testid, states, tutorial key and connections. The
RPC catalogue at the end lists every `platform_*` and tenant-facing RPC with parameters.

## How to read a screen entry

| Field | Meaning |
|---|---|
| screenId | The Appendix A id (e.g. `OA-05`). One screen per id. |
| purpose | One sentence: what the screen is for. |
| route / location | Where it is mounted (a tab, the Audit File window, a drawer, a route). |
| rights | The session right(s) required; a caller without them sees the refusal, never the panel. |
| data functions | The exact `src/data/*.ts` exports the screen calls. Components never reach the client. |
| RPCs / tables | The database functions and tables the screen's data modules reach. |
| testids | Every `data-testid` the screen exposes. |
| states | loading / empty / error / ready / denied, named exactly. |
| tutorial key | The `tutorialKeys.json` key the screen binds its drawer to. |
| connections | Inbound and outbound navigation to other screens. |
